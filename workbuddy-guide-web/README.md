# WorkBuddy 全景数据站

把五套 WorkBuddy 资料包（旗舰手册 / 基础手册 / 128 页速通包 / 保姆级手册与视频 / WorkBuddy×ima 全套）里的场景、指令、案例、路线、排错经验，重新裁剪成一张可检索、可筛选、可复制的单页数据站。

> 说明：全站文案为二次整理后的原创表述，只保留可核实的产品事实（产品名、模式名、模块划分、数字口径、官方链接），不逐段搬运原文。

## 打开方式

双击 `index.html` 即可，无需服务器、无需联网、无外部依赖（数据全部内联在 JS 文件中，file:// 直接可用）。

建议浏览器：Chrome / Edge 111+（使用了 `color-mix()` 与 CSS 变量；不支持时会自动降级为纯色）。

## 推荐阅读顺序

页面现在按五个章节组织，而不是把 11 个区块平铺：

1. **认识**：产品认知、能力六层
2. **上手**：学习路线与排错、场景矩阵
3. **做事**：指令工坊、案例库、专题与模板
4. **固化**：岗位与行业、知识库、自动化可靠性
5. **查证**：42 篇资料原文与全文检索

首屏的「阅读地图」和左侧分组导航都可以直接跳到对应章节。数据仍然全部保留，原文库单独作为证据层，避免和方法总结混在一起。

## 目录结构

```
workbuddy-site/
├── index.html              页面结构（11 个区块 + 页脚）
├── assets/
│   ├── theme.css           设计系统：配色、栅格、卡片、响应式、打印外的一切
│   ├── data-core.js        产品认知、汇总范围、岗位与行业、自动化、知识库、路线、FAQ、来源
│   ├── data-scenes.js      100 个场景、5 种指令口径、63 个应用案例、12 个深案例
│   └── app.js              渲染 + 交互（筛选、搜索、指令生成、复制、主题、导航高亮、原文阅读器）
├── content/                【原文数据】由 tools/build_docs.py 自动生成，不要手改
│   ├── docs-index.js       文档目录：标题、资料包、格式、字数、页数、摘要、大纲
│   └── docs-g1..g5.js      五个资料包各自的正文（按块的数组，含页码标记）
└── tools/
    ├── build_docs.py       把 PDF / DOCX / MD / CSV / TXT 抽成上面的数据结构
    └── ocr_cache.py        扫描页 OCR（逐页渲染 + 识别 + 落盘缓存，可中断重跑）
```

## 内容来源：原文全都进了数据

站点里出现的每一句话都来自这五套资料，路径是「原文件 → 抽取脚本 → `content/*.js` → 页面」：

| 环节 | 做什么 |
| --- | --- |
| `build_docs.py` | 遍历五套资料包，按格式解析：PDF 按页抽文字（保留页码），DOCX 按段落样式分标题/列表/表格，MD 按标记，CSV 转表格 |
| 扫描页 | 单页可提取字符 < 20 就当作扫描页，走 `ocr_cache.py` 的 OCR 结果；识别文本与普通页一样并入同一篇 |
| 去重 | 文件级：md5 相同的只留一份（五套资料里有大量重复拷贝）。内容级：正文指纹相同的多格式版本（docx / pdf / md / txt 各一份）只保留格式最全的一份正文，其余在目录里标注「重复」并指向保留版 |
| 输出 | `content/docs-index.js`（目录，小文件）+ `content/docs-gN.js`（正文，按资料包分文件） |

所以站点可以脱离 Word / PDF 独立阅读和检索；页面上的「打开原文件」只是溯源用，文件搬家后会失效，不影响阅读。

### 重建原文数据

```bash
python tools/build_docs.py --dry     # 先看统计：每篇多少字、多少页、哪些是扫描页
python tools/build_docs.py           # 生成 content/docs-index.js 与 docs-g1..g5.js
python tools/ocr_cache.py            # 扫版 PDF 补 OCR（缺缓存才跑，可中断重跑）
```

依赖：`pypdf`、`python-docx`；OCR 另需 `rapidocr-onnxruntime`、`pypdfium2`（纯 CPU，约每页 20~30 秒，识别结果缓存在 `tools/.ocr-cache/`，按文件指纹分目录，换机器也不会重复识别）。

当前离线产物的实测口径：**42 篇文档 / 427,221 字 / 238 页扫描页 OCR**，正文数据合计约 1.3 MB（`docs-g1` 281 KB、`docs-g2` 26 KB、`docs-g3` 509 KB、`docs-g4` 363 KB、`docs-g5` 为空即该包内容全部与速通包重复、`docs-index` 61 KB）。OCR 一轮约 30 分钟（3 进程）。

## 交互（哪里能点）

| 能点的东西 | 会发生什么 |
| --- | --- |
| 左侧 / 顶部导航 | 平滑跳到对应区块，滚动时自动高亮当前区块 |
| 首页十个数字卡 | 点一下跳到它对应的区块 |
| 场景卡（整张卡都能点） | 把指令工坊切到这个场景并跳过去，右下角按钮功能相同 |
| 分类 / 受众筛选胶囊 | 过滤场景，分类还会同步指令工坊 |
| 指令工坊的下拉与口径胶囊 | 实时重算指令文本，「复制指令」「换下一条」 |
| 案例卡 | 点一下复制这条做法的「起手指令」 |
| 知识库体检问题 | 点一下复制成一句可直接粘贴的限定式提问 |
| FAQ 每一条 | 展开 / 收起 |
| 原文库：搜索框 | 全文检索所有资料，按命中数排序，左侧列出命中段落（关键词高亮） |
| 原文库：命中条目 | 打开那篇文档并滚到命中的那一段，段落会短暂描边 |
| 原文库：资料包 / 格式胶囊 | 过滤文档清单，搜索时同样生效 |
| 原文库：文档清单 | 右侧换成该篇全文（标题分级、列表、表格、页码标记），长文可「继续往下读」 |
| 原文库：大纲胶囊 | 跳到该篇的某个小标题 |
| 原文库：「复制全文」/「打开原文件」 | 复制整篇纯文本 / 用系统程序打开原 PDF、DOCX |
| 右上角 ◐ | 深色 / 浅色切换，选择记在 localStorage |

其余卡片是纯内容（悬停只会轻微描边，没有指针手势），点它不该有反应——这是有意区分的：**能点的会有手势和描边高亮，不能点的不装能点**。

如果整页都点不动、场景区是空的，页面顶部会自动弹出红色提示条，说明脚本没有执行（常见于预览窗口的沙箱限制），按提示用浏览器直接打开即可；如果浏览器禁用了脚本，会看到 `<noscript>` 提示。

## 怎么往里加东西

- 加场景：在 `data-scenes.js` 的 `scenes` 里加一条 `{ n, c, g, o, k }`，分类 key 用 `categories` 里已有的十个之一；场景数、筛选计数、指令工坊会自动更新。- 加指令口径：在 `versions` 里加一条 `{ key, name, tag, desc, tpl }`，`tpl` 里用 `{n}` `{g}` `{o}` 占位。
- 加案例：`appCases` 里加 `{ n, c, how, out }`，分类会自动出现在筛选条上。
- 改文案配色：`theme.css` 顶部两组 CSS 变量（`:root` 与 `[data-theme="light"]`）。
- 加原文：把文件丢进对应资料包目录，跑 `python tools/build_docs.py`；扫描件先跑 `python tools/ocr_cache.py` 补 OCR。目录、字数、检索会一起更新。

## 边界

- 不是官方说明书；界面、套餐、入口以官网当前版本为准。
- 产品数字（专家数量、积分额度、安装体积）来自资料包记录，可能随版本变化。
- 法律、医疗、财税、投资相关内容只做资料整理，不构成专业意见。
- 高风险文件操作请先用复制件试跑，并保留原件与变更日志。
